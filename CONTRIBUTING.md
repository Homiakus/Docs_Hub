# Руководство по вкладу в разработку Docs_Hub

Спасибо за ваш интерес к развитию **Docs_Hub**! Данное руководство содержит правила и стандарты для поддержания высокого качества кода, безопасности и архитектурной чистоты проекта.

## Принципы разработки

1. **Модульный монолит**: Проект развивается как монолитный сервис на Go. Прямые SQL-запросы не должны присутствовать в HTTP-хэндлерах.
2. **Централизованная авторизация**: Каждая операция с документами и файлами обязана проверяться через единую службу авторизации (`Authorizer`).
3. **Безопасность по умолчанию**: Все новые эндпоинты должны поддерживать CSRF-защиту, строгое ограничение скорости (Rate Limiting) и минимальные необходимые привилегии.
4. **Тестирование**: Любое исправление дефекта должно сопровождаться регрессионным тестом в пакете `*_test.go`.

## Рабочий процесс (Workflow)

1. Создайте feature-ветку от `main` (формат: `feat/feature-name` или `fix/issue-description`).
2. Внесите изменения, соблюдая стиль кода `gofmt` и рекомендации `staticcheck`.
3. Убедитесь, что все тесты проходят локально: `go test -v -race ./...`.
4. Создайте Pull Request в репозиторий.
