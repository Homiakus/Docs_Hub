## 1. Продуктовые сценарии и матрица типов контента (Product Discovery)

Docs_Hub обслуживает спектр задач от оперативных заметок и баз знаний до строгой технической документации, нормативных регламентов и публичных long-form публикаций. Редактор не должен быть универсальным «комбайном с 50 кнопками» — он обязан предоставлять адаптивную среду под 10 ключевых архетипов контента.

### 1.1. Матрица архетипов контента

| Архетип | Структура и глубина | Обязательные метаданные | Ключевые Markdown-конструкции | Медиа и интерактив | Валидация и Quality Gates |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **Статья (Knowledge Article)** | Введение, тезисы, тело (H2/H3), выводы, связанные ссылки. 800–2500 слов. | `title`, `space_id`, `category_id`, `tags`, `author`, `status` | Callouts (`> [!NOTE]`), списки, inline-code, цитаты, wiki-links `[[slug]]`. | WebP скриншоты с `alt`, схемы Mermaid, таблицы данных. | Проверка битых внутренних ссылок, обязательные `alt` у картинок, уникальный H1. |
| **Новость / Дайджест (Company News)** | Лид (lead paragraph), хроника событий, медиа-галерея, CTA. 200–600 слов. | `title`, `published_at`, `visibility`, `pinned`, `target_audience` | Выделение текста (bold/italic), списки изменений, короткие цитаты. | Баннер (hero image), видео-эмбед, галерея изображений. | Контроль длины заголовка, наличие hero-изображения, дата публикации. |

| **Landing / Портальный контент** | Hero-секция, grid-карточки преимуществ, FAQ, call-to-action кнопки. 300–800 слов. | `title`, `slug`, `seo_title`, `seo_description`, `og_image` | Custom directives (`:::grid`, `:::cta`), крупные заголовки, акцентные кнопки. | Hero-баннеры, иконки, векторная графика, встроенные формы. | SEO-валидация (title 50–60 симв., description 120–160 симв.), доступность контраста. |

## 2. Модель прогрессивного раскрытия UX (Beginner → Regular → Power User)

Вместо трех изолированных режимов интерфейс Docs_Hub реализует **единую адаптивную поверхность с прогрессивным раскрытием возможностей (Progressive Disclosure)**:

```text
┌─────────────────────────────────────────────────────────────────────────────────┐
│                               Docs_Hub Editor UX                                │
├─────────────────────────┬────────────────────────────┬──────────────────────────┤
│    Beginner Layer       │    Regular Editor Layer    │     Power User Layer     │
├─────────────────────────┼────────────────────────────┼──────────────────────────┤
│ • Видимый тулбар (9 кн) │ • Markdown shortcuts (#, >)│ • Command Palette (⌘+K)  │
│ • Модальные пикеры      │ • Выделение + Hotkeys (⌘+B)│ • Slash-команды (/table) │
│ • Drag-n-drop загрузка  │ • Wiki-link автокомплит [[ │ • Редактор Frontmatter   │
│ • Шаблоны документов    │ • Быстрая вставка таблиц   │ • Vim/Sublime keymaps    │
│ • Контекстные подсказки │ • In-Place Live Preview    │ • AST-навигация и Diff   │
└─────────────────────────┴────────────────────────────┴──────────────────────────┘
```

1. **Новичок (Beginner)**:
   - Входит на чистый лист с ненавязчивым placeholder-руководством.
   - Использует верхний компактный тулбар и готовые шаблоны (Architecture Doc, Runbook, Meeting Notes, Decision Record).
   - Вставляет медиа простым перетаскиванием (drag-and-drop) или вставкой скриншотов (`Ctrl+V`) прямо в документ с автоматической визуализацией.
   - Видит визуальные плашки валидации (например: *«Добавьте описание для картинки»*).
2. **Опытный редактор (Regular Editor)**:
   - Пишет не отрывая рук от клавиатуры: `# ` для заголовков, `- ` для списков, `> ` для цитат.
   - Работает в режиме **Obsidian Live Preview**: текст форматируется прямо на глазах, а медиа, формулы и диаграммы встраиваются внутрь полотна.
   - Выделяет слово и нажимает `Ctrl+B` (жирный), `Ctrl+K` (вставка ссылки с автопоиском).
   - Использует конструкцию `[[` для связи со статьями корпоративной wiki с мгновенной фильтрацией.
3. **Power User & Developer**:
   - Оперирует Command Palette (`Ctrl/Cmd + K` или `Ctrl/Cmd + Shift + P`) для выполнения любых CMS-действий.
   - Использует Slash-команды (`/table 4x4`, `/callout warning`, `/mermaid sequence`, `/image`).
   - Напрямую редактирует YAML Frontmatter метаданных при необходимости.
   - Мгновенно переключается между In-Place Live Preview, Split Dual-Pane и Raw Source через `Ctrl+Shift+E`.

### 3.1. Механика работы In-Place Live Preview
1. **Source/Decoration Hybrid (CodeMirror 6 / Decoration Engine)**:
   - Когда каретка находится вне блока (например, `**жирный текст**` или `## Заголовок`), синтаксические маркеры скрываются, и элемент рендерится как отформатированный HTML-узел.
   - Когда каретка заходит внутрь блока (например, клик на жирный текст), маркеры `**` мгновенно раскрываются для точного посимвольного редактирования.
2. **Прямой рендеринг виджетов в поток документа (Inline Widgets)**:
   - Изображения `![alt](url)` отображаются прямо в полотне текста с поддержкой изменения размера и зума.
   - Диаграммы Mermaid (```mermaid) отображаются в виде интерактивного SVG прямо в документе; клик по диаграмме открывает ее код для редактирования.
   - Математические формулы KaTeX (`$$...$$`) и таблицы рендерятся визуально прямо в строке.
   - Callout-блоки (`> [!NOTE]`) отображаются стилизованными цветными плашками.

### 3.2. Режимы просмотра редактора
- **Obsidian Live Preview (По умолчанию)**: Бесшовный гибридный режим — пишите чистый Markdown, видите результат прямо в документе.
- **Split Dual-Pane Mode**: Классический двухпанельный режим (Editor слева, Production Preview справа) с синхронизированным скроллом.
- **Raw Markdown Source**: Чистый моноширинный код для разработчиков и Git-энтузиастов.
- **Full Reading Preview**: Боевой режим чтения с полной симуляцией стилей портала.

## 4. Прямая вставка и обработка медиа внутри документа (In-Document Media)

Медиа вставляется **напрямую в документ в точку курсора** без необходимости открывать отдельные файловые менеджеры или покидать редактор.

```text
Сценарии вставки медиа прямо в документ:
├── 1. Вставка из буфера обмена (Paste Ctrl+V):
│   ├── Пользователь нажимает Ctrl+V со скриншотом в буфере
│   ├── В точку курсора вставляется анимированный токен:
│   │   ![Загрузка screenshot-14-22.webp 45%...](/static/img/upload-progress.svg)
│   ├── Фоновый асинхронный POST /api/uploads оптимизирует файл (WebP/AVIF)
│   └── Токен плавно превращается в интерактивный инлайн-виджет изображения
├── 2. Прямое перетаскивание (Drag & Drop в поток текста):
│   ├── Перетаскивание файла из проводника/десктопа в конкретную строку статьи
│   ├── Появление горизонтального индикатора места вставки (Drop Indicator)
│   └── Моментальная вставка и инлайн-превью
├── 3. Вставка видео, аудио и документов:
│   ├── Вставка видео (/video или перетаскивание .mp4/.webm) ──▶ инлайн HTML5-плеер
│   ├── Вставка аудио (/audio или .mp3/.wav) ──▶ инлайн аудио-плеер с таймлайном
│   └── Вставка PDF (/pdf или .pdf) ──▶ интерактивная карточка вложения с предпросмотром
└── 4. Инлайн-управление медиа-виджетом:
    ├── Наведение на картинку открывает плавающий тулбар: [✎ Alt-текст] [💬 Подпись] [↔ 50%/75%/100%] [🗑]
    └── Двойной клик раскрывает полноэкранный Lightbox для детального просмотра
```

## 7. Контекстный тулбар, Command Palette (`Ctrl+K`) и Slash-команды (`/...`)

### Компактный тулбар (9 основных кнопок)
`[ B ]` `[ I ]` `[ </> ]` `|` `[ H2-H4 ▾ ]` `[ ☷ Списки ▾ ]` `[ ❞ Цитата ]` `|` `[ 🔗 Ссылка ]` `[ 📷 Медиа ]` `[ ⋯ Еще ]`

### Slash-команды (`/...`) с прямой генерацией чистого Markdown
- `/image` $\to$ открывает диалог выбора или зоны дропа прямо в тексте;
- `/table` $\to$ вставляет чистую Markdown-таблицу;
- `/note`, `/warning`, `/tip` $\to$ вставляет визуальный Callout;
- `/mermaid` $\to$ вставляет блок диаграммы Mermaid;
- `/video` $\to$ вставляет контейнер видеоплеера;
- `/code` $\to$ вставляет блок кода с выбором языка.

## 8. Автосохранение, история версий и разрешение конфликтов

1. **Мгновенный локальный кэш (IndexedDB)**: Сохранение каждого символа. Гарантия нулевой потери данных при сбое браузера.
2. **Фоновый серверный Autosave (900мс)**: Автоматическая синхронизация черновика с сервером Docs_Hub.
3. **Оптимистические блокировки (`lock_version`) и 3-Way Diff**: При параллельном редактировании документа несколькими авторами система открывает визуальный резолвер для бесконфликтного слияния правок.

## 9. Сохранение дизайн-системы и стандарты производительности

- **Дизайн-система**: Полная интеграция с фирменными токенами `Neo-Swiss Editorial` (`--surface-canvas`, `--action-primary`, `--transition-normal`, стеклянный блюр `backdrop-filter: blur(16px)` и поддержка темной/светлой темы).
- **Производительность**: Задержка ввода $< 16\text{ms}$ (60 FPS), мгновенный отклик при наборе текста, масштабирование на статьи объемом до $150\,000$ слов.
- **Доступность**: Соответствие стандарту **WCAG 2.2 AA** с поддержкой управления только с клавиатуры и чтения скринридерами.
